# 100,000-object boards — 2026-10-21

Released as Pencils 0.18.0. Markdown remains the vault format; boards remain portable JSON Canvas files.

## Capacity and implementation

- 100,000 nodes, 200,000 connectors, 500 frames. Nodes and connectors have separate limits. Coordinates are bounded to ±1,000,000, board HTTP requests to 128 MB, and native file imports to 64 MB. File size and complexity can become limiting before object count.
- Camera updates reuse a spatial index, frame membership, connector routes and a cached minimap. Geometry is invalidated on board edits. Normal views keep at most 240 detailed cards/connectors; overview zoom uses bitmap shapes/lines and promotes selected objects to editable detail. Connector labels, arrowheads and exact obstacle routing are shown in detailed SVG; dense bitmap connectors use simplified paths. Native export preserves complete geometry.
- Guarded field deltas replace base-plus-whole-board uploads. Independent edits merge; overlapping edits remain explicit conflicts. Lost acknowledgements are retried idempotently. Browser recovery stores the changes and touched originals rather than two full board snapshots. Undo/history remain in the vault.

## Measurements

Production assets, Chromium 149.0.7827.55, Node 22.22.1, AMD Ryzen 9 9950X3D, local isolated vault, 1440×1050 viewport. Synthetic sticky cards; sparse layouts use 320-pixel spacing and dense layouts use 30-pixel spacing (deliberate overlap). Pan samples dispatch a wheel event and wait two animation frames; these are interaction timings, not FPS. No Miro runtime benchmark was performed.

| Scenario | Load ms | Pan median / p95 ms | API save ms | Move request bytes |
|---|---:|---:|---:|---:|
| sparse-100000 | 1522 | 33 / 40 | 1275 | 207 |
| maximum-100000 | 3424 | 33 / 53 | 3100 | 208 |
| dense-100000 | 3590 | 109 / 124 | 2763 | 206 |

A browser integration test imported a 28 MiB native file with 100,000 nodes and 200,000 connectors, edited a card, undid it, interrupted a save, reloaded, reconnected and verified every object/connector remained in the native file. The full UI edit-and-save interaction took 6.34 seconds, with a 458-byte request; its recoverable draft was 662 bytes. Fit and selection from the bitmap overview passed with no browser errors.

The earlier dense 2,500-node / 5,000-connector fixture improved from 826/988 ms median/p95 to 33/98 ms in an intermediate comparison. Existing 5,000-object interaction checks passed (held panning, stable DOM during zoom, touch pinch/pan and pressure-sensitive drawing).

## Practical limits and remaining work

This is validated desktop capacity, not a promise of smooth editing with every object type or 100 simultaneous people on one maximum-sized board. Spaced boards navigate well; the extreme overlapping fixture remains around 109 ms median per sampled pan. The previous p95-under-50-ms and save-under-250-ms aspirations are not met at the maximum. Low-memory phones/tablets and simultaneous 100-person editing have not been capacity-qualified.

Initial snapshots, remote refreshes, local checkpoints, complete vault-file writes/history and save responses still scale with total board size. Single-card writes took 1.3–3.1 seconds at 100k, and complete browser interactions take longer. Heavy images, rich task cards, tables, line jumps and pen strokes cost more than these fixtures. Future improvements should add compact save acknowledgements and remote deltas, region loading, incremental index updates after edits, and a worker/retained scene for dense overview rendering. The portable vault snapshot can remain authoritative.

Miro publishes a maximum of 100,000 total objects, warns that performance can be affected from 1,000, and recommends fewer than 5,000 for a better experience. Pencils counts nodes and connectors separately, so these are not identical counting rules or evidence of equal speed. Source verified 2026-10-21: [Miro board performance guidance](https://help.miro.com/hc/en-us/articles/360013588560-Board-performance-and-loading-issues).

## Validation and reproduction

232 unit/model tests, type and syntax checks, board browser regression, board interaction/performance regression, and full-capacity browser import/edit/undo/recovery all passed. Browser fixtures never use the user's vault.

```sh
npm run check
npm test
npm run build
node test/canvas-browser.mjs
node test/canvas-performance.mjs
node test/canvas-large-board.mjs
CAPACITY_CASES=sparse-100000,maximum-100000,dense-100000 node test/canvas-capacity.mjs
```

Deployment retains the 0.17.0 rollback image and a full pre-upgrade vault archive in `.release-backups/`. The Work drive remounted at `Work1`; deployment now binds the intact vault at that path.
