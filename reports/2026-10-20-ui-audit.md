# Pencils full UI audit

**Resolution update — 20 October 2026:** All 15 findings below have been addressed, verified and deployed in **0.16.8**. See [fix verification](#fix-verification--20-october-2026). The original findings and score below are retained as the audit baseline.

20 October 2026 · Working tree at package version **0.16.5** · UIAudit / Impeccable technical audit

**Implementation integrity verdict: FAIL against the shared interaction contract.** Pencils has a coherent, product-specific visual system, shared navigation and substantial reusable UI. However, the same task exposes different comment histories, closing its editor changes focus unpredictably, and responsive overrides hide important task information. These are verified behavioural and implementation inconsistencies.

The bundled Impeccable detector could not run: engine 0.1.5 is not installed and its default cache location is not writable. Both the context and detector commands exited with code 127. No `PRODUCT.md` or `DESIGN.md` was present. This verdict uses browser observations, axe-core results and source inspection; it is **not a detector-generated verdict**.

**15 findings: 0 P0, 9 P1, 6 P2, 0 P3.** Findings are counted by problem, not by the number of affected elements or repeated scans. P1 means significant difficulty or a verified accessibility failure; P2 means a limitation with a practical workaround.

Address these first:

1. Make comments on a Board task card and its task editor resolve to the same conversation.
2. Keep task titles visible in phone List/Tree, and restore IDs in phone Table.

This was an audit only. Application code, live project data, version numbers and deployment were not changed.

## P1 — major findings

### F01. Board-card comments and task-editor comments are different conversations

**Category:** Implementation integrity  
**Location:** [canvas-pro.js](/run/media/george/Work/Projects/pencils/public/canvas-pro.js:457), [features.js](/run/media/george/Work/Projects/pencils/public/features.js:438), [board-comments.js](/run/media/george/Work/Projects/pencils/public/board-comments.js:133)

**Evidence:** Added “Audit: visible on the board task card” through the comment icon on a real task card. Opening that same task’s editor and Comments then displayed “No comments yet.” The saved comment existed on the Board node; the task had no corresponding comment.

**Impact:** A conversation appears missing when users switch entry points. Multiple Board cards for one task can accumulate separate discussions without their scope being apparent.

**Recommendation:** Resolve comments on finalised task cards through the task-comments adapter. Keep object comments for sticky notes, frames and draft objects. Preserve existing node threads through an explicit migration or a clearly labelled legacy discussion; do not discard them.

**Acceptance:** Comment from either entry point, reload, and open the same task from another view or Board card: the thread and count agree.

**Standard:** Product identity and data consistency; no WCAG failure asserted.  
**Suggested command:** `/impeccable harden`

[Reproduction screenshot](assets/ui-audit-2026-10-20/confirm-chromium-comment-ownership.png)

### F02. List and Tree put every task title outside the initial phone viewport

**Category:** Responsive design  
**Location:** [task-tools.css](/run/media/george/Work/Projects/pencils/public/task-tools.css:60), [controls.css](/run/media/george/Work/Projects/pencils/public/controls.css:92)

**Evidence:** At 390px and 320px, the first task title starts at **x=645px**. Coarse-pointer rows have a minimum width of 884px, and the expander/spacer, drag handle, checkbox, open action, type, ID and metadata precede the title. The problem was also reproduced in WebKit.

**Impact:** Users initially see controls and IDs without the task’s name. Horizontal scrolling is possible, but reading a task and reaching its left-side actions require moving between different parts of the row.

**Recommendation:** Preserve the requested compact desktop order. Add one shared narrow-screen row variant that prioritises ID/title and exposes secondary fields through a second line or compact details control. Keep the same variant in List and Tree, with hierarchy indentation only where needed.

**Acceptance:** At 320px, 390px and tablet portrait, each row initially shows a meaningful title and a reachable open action.

**Standard:** Responsive usability; no automatic reflow failure is inferred solely from intentional horizontal scrolling.  
**Suggested command:** `/impeccable adapt`

[List](assets/ui-audit-2026-10-20/390-light-list.png) · [Tree](assets/ui-audit-2026-10-20/390-light-tree.png)

### F03. Table hides task IDs while retaining the ID column

**Category:** Responsive design / implementation integrity  
**Location:** [styles.css](/run/media/george/Work/Projects/pencils/public/styles.css:1833), [grid.js](/run/media/george/Work/Projects/pencils/public/grid.js:187)

**Evidence:** The broad mobile `.task-id { display: none; }` rule hides Table’s ID text. At 390px, the ID column remains visibly blank. Computed styles confirm `display: none` for `REL-1`, `REL-2` and `REL-3`. WebKit reproduced this at both 390px and 750px.

**Impact:** Users cannot identify rows by ticket ID, and the empty column consumes scarce horizontal space.

**Recommendation:** Remove or narrowly scope the legacy hiding rule. Keep Table IDs visible regardless of viewport; consider a compact identity column on phones without changing saved desktop column preferences.

**Acceptance:** An ID column that is enabled always contains visible IDs in both browsers and themes.

**Standard:** Content availability and responsive consistency.  
**Suggested command:** `/impeccable adapt`

[Chromium](assets/ui-audit-2026-10-20/390-light-table.png) · [WebKit](assets/ui-audit-2026-10-20/webkit-390-table.png)

### F04. Closing task details loses the keyboard user’s place

**Category:** Accessibility / implementation integrity  
**Location:** [board-task-editor.js](/run/media/george/Work/Projects/pencils/public/board-task-editor.js:126), [app.js](/run/media/george/Work/Projects/pencils/public/app.js:1129)

**Evidence:** From List, Tree, Table and Kanban, Escape from the editor’s title field moves focus to **New task**, regardless of which task was opened. Clicking the close button leaves focus on **BODY** in all four checked views.

**Impact:** Reviewing several tasks requires repeatedly finding the previous row. Close and Escape also have different outcomes.

**Recommendation:** Capture the invoking element and task identity when opening. On close, restore the opener or its replacement after a rerender; use a nearby row or view heading only when the task no longer exists. Apply the same rule to every close path.

**Acceptance:** Open a task halfway down each view, close by Escape and X, and continue keyboard navigation from the original task with scroll position retained.

**Standard:** Focus-order usability. Returning to the invoker or a logical replacement follows [W3C dialog focus guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/); the task editor itself is nonmodal, so this is not a claim that it must trap focus.  
**Suggested command:** `/impeccable harden`

### F05. Attaching a file requires drag and drop

**Category:** Accessibility  
**Location:** [task-attachments.js](/run/media/george/Work/Projects/pencils/public/task-attachments.js:21), [task-attachments.js](/run/media/george/Work/Projects/pencils/public/task-attachments.js:169)

**Evidence:** The editor contains no file input. Its attachment instruction is a noninteractive paragraph. Upload handling is registered only for drag events; preview buttons become available only after a file has been attached.

**Impact:** Keyboard users cannot start an upload. Phone users without an external drag source also lack an obvious attachment path.

**Recommendation:** Preserve the requested removal of the separate “Attach file” button. Make the existing drop instruction a keyboard-operable file-selection affordance, backed by a hidden file input; support Enter/Space and touch. Keep drag and drop as the parallel path.

**Acceptance:** Attach a file using only the keyboard, and using touch file selection, with the same progress/error feedback as a drop.

**Standard:** [WCAG 2.1.1 Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html).  
**Suggested command:** `/impeccable harden`

### F06. Board task cards nest interactive controls inside a button role

**Category:** Accessibility  
**Location:** [app.js](/run/media/george/Work/Projects/pencils/public/app.js:1558), [canvas-pro.js](/run/media/george/Work/Projects/pencils/public/canvas-pro.js:473)

**Evidence:** The task’s Board node has `role="button"` and `tabindex="0"`, while its contents include comment/open buttons and priority/status/assignee controls. Axe reported `nested-interactive` on the populated card in both themes and viewport sizes.

**Impact:** Assistive technologies can flatten or misrepresent the card’s child controls, creating ambiguous actions and unexpected focus stops.

**Recommendation:** Give the card a suitable labelled container role and an explicit selection/open control. Preserve Board selection, movement shortcuts and accessible names without making the entire interactive subtree a button.

**Acceptance:** The accessibility tree exposes the card’s individual actions and fields; keyboard selection and inline editing still work; the nested-interactive rule passes.

**Standard:** Name/role/value and valid interactive semantics, associated with WCAG 4.1.2.  
**Suggested command:** `/impeccable harden`

### F07. Markdown checklists render unnamed checkbox controls

**Category:** Accessibility  
**Location:** [markdown.js](/run/media/george/Work/Projects/pencils/public/markdown.js:6), [task-description.js](/run/media/george/Work/Projects/pencils/public/task-description.js:4)

**Evidence:** Rendering `- [ ] Keyboard access` and `- [x] Save changes` produces disabled checkbox inputs with no label association. Axe reported `label` failures in the task description, populated Board card and document content.

**Impact:** The checked state and the item text are not reliably connected for assistive technology.

**Recommendation:** Fix this once in the shared Markdown renderer. Associate the text with the checkbox, or render a properly named read-only checklist representation. Preserve Markdown round-tripping, checked states and sanitisation.

**Acceptance:** Checked and unchecked items have meaningful accessible names in Documents, task editors, previews and Board content.

**Standard:** WCAG 1.3.1 / 4.1.2 as identified by the form-label scan.  
**Suggested command:** `/impeccable harden`

### F08. Visible date labels are missing from their accessible names

**Category:** Accessibility  
**Location:** [app.js](/run/media/george/Work/Projects/pencils/public/app.js:970)

**Evidence:** A List/Tree date button visibly says **25 Oct**, while its accessible name is only **Dates for Review design**. Axe reports `label-content-name-mismatch` on these dated rows.

**Impact:** A voice-control user saying the displayed date may not activate the button; a screen-reader user hears the action but not the visible due date.

**Recommendation:** Derive the accessible name from the displayed date plus task context, for example “25 Oct — edit dates for Review design.” Keep full start/due values available as a description.

**Acceptance:** The displayed date is included in the computed accessible name, in every supported date format.

**Standard:** [WCAG 2.5.3 Label in Name](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html).  
**Suggested command:** `/impeccable harden`

### F09. Sticky-note text does not maintain contrast for supported custom fills

**Category:** Theming / accessibility  
**Location:** [styles.css](/run/media/george/Work/Projects/pencils/public/styles.css:1431), [appearance.css](/run/media/george/Work/Projects/pencils/public/appearance.css:459), [node-layout.js](/run/media/george/Work/Projects/pencils/public/node-layout.js:5)

**Evidence:** A note with the sample custom fill `#f4e1a1` retains hard-coded light-theme text `#70673e`. Axe measured **4.36:1** at normal-weight 16px text in the phone Board. This finding concerns that supported custom fill, not every default note.

**Impact:** Users can choose a valid note colour that makes its content harder to read. Dark mode uses a different fixed text colour rather than deriving it from the fill.

**Recommendation:** Compute or select a readable foreground for the actual object fill, using one shared helper for notes/shapes. Preserve user-selected fills and explicit text colours, with clear contrast feedback for overrides.

**Acceptance:** Test default fills plus representative pale, saturated and dark custom fills in both themes and exported content.

**Standard:** Normal-size text requires at least 4.5:1 under [WCAG 1.4.3 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).  
**Suggested command:** `/impeccable colorize`

## P2 — improvements with practical workarounds

### F10. Some touch controls meet the shared height but remain too narrow

**Category:** Responsive design / implementation integrity  
**Location:** [task-tools.css](/run/media/george/Work/Projects/pencils/public/task-tools.css:29), [planning.js](/run/media/george/Work/Projects/pencils/public/planning.js:40), [canvas-pro.js](/run/media/george/Work/Projects/pencils/public/canvas-pro.js:473), [controls.css](/run/media/george/Work/Projects/pencils/public/controls.css:92)

**Evidence:** Phone Table’s open-task button is **20×44px**. Board card comment/open controls are approximately **24×37px** at the sampled 85% canvas zoom. Single-line Calendar agenda task buttons measure approximately **354×21px**.

**Impact:** Important actions are harder to tap accurately even though adjacent controls follow the 44px contract.

**Recommendation:** Include width and actual hit area in shared control variants. Keep small icons and checkbox visuals, but provide full touch targets. For canvas controls, use screen-space affordances or a zoom-aware target floor.

**Standard:** Violates this project’s 44px touch-target rule. This is **not** a blanket WCAG failure: [WCAG 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) uses a 24px minimum with spacing and other exceptions.  
**Suggested command:** `/impeccable adapt`

### F11. Phone toolbars and auxiliary panels leave too little useful working space

**Category:** Responsive design  
**Location:** [project-layout.css](/run/media/george/Work/Projects/pencils/public/project-layout.css:88), [project-layout.js](/run/media/george/Work/Projects/pencils/public/project-layout.js:40), [task-tools.css](/run/media/george/Work/Projects/pencils/public/task-tools.css:1056)

**Evidence:** At 390×844, Table’s scroll area starts at **y=464px** and is **331px high**. The stacked controls use over half the screen before the table header. Mobile comments cover almost all task fields while leaving an approximately 50px strip of the editor exposed underneath.

**Impact:** Users see few rows and repeatedly scroll or dismiss panels to resume work.

**Recommendation:** Offer a shared compact phone toolbar with search and a View options panel containing saved-view/group/sort/filter controls. Preserve all existing actions. At narrow widths, use a clear Details/Comments/History switch within the task panel instead of overlapping panels.

**Standard:** Usability and workspace allocation; no automatic WCAG failure asserted.  
**Suggested command:** `/impeccable adapt`

### F12. Opening a basic task view downloads the full feature graph

**Category:** Performance  
**Location:** [index.html](/run/media/george/Work/Projects/pencils/public/index.html:18), [app.js](/run/media/george/Work/Projects/pencils/public/app.js:43), [features.js](/run/media/george/Work/Projects/pencils/public/features.js:1), [server/index.js](/run/media/george/Work/Projects/pencils/server/index.js:723)

**Evidence:** A cold List load requested **154 resources**, with approximately **1.70MiB** of encoded bodies: **1.27MiB JavaScript**, **247KiB CSS**, and the **161KiB Manrope font**. Canvas, drawing, integration and other feature modules load before those views are used. Under a controlled simulation of 1.6Mbit/s download, 150ms latency and 4× CPU slowdown, the first task row appeared after **10.77 seconds**.

**Impact:** Cold loads on slower connections/devices pay for unused features. This is a lab observation, not a field percentile or a claim that a local LAN always takes ten seconds.

**Recommendation:** Load specialist view controllers on first use; bundle the shared startup path and split large optional modules. Serve compressed production assets with versioned caching while preserving offline behaviour and safe updates. Keep locally hosted fonts; the cold basic view loaded only the chosen font, not all eight.

**Acceptance:** Compare cold/warm view readiness and transferred bytes with the same fixture and throttle. Retain Board preload/culling and document recovery tests.

**Standard:** Measured performance; no WCAG criterion.  
**Suggested command:** `/impeccable optimize`

### F13. Invalid autosave can be dismissed without acknowledging the unsaved edit

**Category:** Implementation integrity  
**Location:** [task-autosave.js](/run/media/george/Work/Projects/pencils/public/task-autosave.js:50), [app.js](/run/media/george/Work/Projects/pencils/public/app.js:1129)

**Evidence:** Clearing an existing task title shows “Complete the required fields to save.” Closing still dismisses the editor. Reopening shows the saved title and a separate “A browser draft is available” restore/discard notice.

**Impact:** Draft recovery works, but the invalid edit disappears from immediate view without a clear decision about keeping it.

**Recommendation:** Respect the flush result when closing. For invalid input, keep the editor open or explicitly offer Keep editing / Keep draft and close. Do not add confirmation to ordinary valid autosaves.

**Acceptance:** Invalid fields remain visible or the user knowingly keeps a draft; valid and offline-queued edits retain their existing smooth close behaviour.

**Standard:** Save-state clarity; no data loss was observed.  
**Suggested command:** `/impeccable harden`

### F14. Kanban manual ordering has no equivalent keyboard action in that view

**Category:** Accessibility / interaction consistency  
**Location:** [kanban-drag.js](/run/media/george/Work/Projects/pencils/public/kanban-drag.js:103), [kanban-drag.js](/run/media/george/Work/Projects/pencils/public/kanban-drag.js:210), [task-reorder.js](/run/media/george/Work/Projects/pencils/public/task-reorder.js:4)

**Evidence:** Source inspection shows Kanban order changes are driven by native drag/drop events; its keyboard handler only cancels an existing drag. **Impact:** Keyboard users must switch views to arrange tasks, and cannot use the same ordering action consistently across layouts.

**Standard:** Keyboard parity. No blanket WCAG 2.1.1 failure is claimed because an equivalent ordering operation exists in another view. Touch drag reliability needs physical-device validation.  
**Suggested command:** `/impeccable harden`

## Systemic patterns and findings excluded from the count

- **Test scope matters more than another base-page smoke test.** The existing accessibility test covers nine views with one simple task, omits Documents, and filters to selected WCAG tags. It cannot expose all rich-checklist, open-panel, long-content and phone regressions. Add representative populated states and semantic assertions alongside scans.
- **Shared height does not guarantee a shared control.** The sizing test measures a selected set of classes. Hit-area width, internal wrappers, canvas transforms and actual content visibility need complementary checks.
- **Global geometry checks miss local problems.** The phone List had document width 390px while its first title started at x=645px. Table similarly passed page-width checks while hiding IDs.
- **The product has competing component rules.** Legacy `.task-id` hiding and Table’s 20px open action survive underneath the newer shared system. Fix the shared rule/variant rather than layering another view-specific override.
- **Reduced motion needs a scoped contract.** `task-tools.css:1070` applies a global `0.01ms` animation/transition reset, and `styles.css:1875` disables all transitions. The Board camera and Kanban also have deliberate reduced-motion branches. No lost state feedback was demonstrated here, so the blanket reset is recorded as maintenance risk, not an invented accessibility failure. Preserve the deliberate alternatives when consolidating it.

Automated output was reviewed rather than treated as a list of confirmed defects:

- The small checkbox **visuals** measured 13px, but their Table labels measured **44×44px** on touch. They are not counted as undersized controls.
- The date-picker day buttons measured **44×44px** in the confirmation pass; an older smaller-target concern does not apply.
- Expected horizontal scrolling in Table, Timeline and Kanban is not itself a defect. F02 concerns the loss of useful task identity in the initial List/Tree viewport.
- Avatar initials triggered repeated label/name warnings. Because these act as symbolic identity graphics with a functional “Personal settings” name, they were not counted as 108 separate failures.
- Calendar’s day-number/ISO-date labels, redundant file-type badges, optional landmark checks and People/Teams heading-order warnings need semantic review. They were not promoted to major failures without stronger evidence.
- Documents removes the contenteditable outline, but a text caret can itself provide a focus indication. The absence of an outline alone was not counted as a WCAG failure.
- One outside-click confirmation clicked a navigational breadcrumb and then timed out looking for the old table. That harness error is excluded from product findings.

## What is working well

- Shared project navigation, view switches and task field colours produce a consistent visual foundation in both themes. The recent compact desktop controls are intentional and should be preserved.
- Documents provides a useful explorer/editor split and a separate phone browsing mode. Rich/Markdown editing, import/export, reload, offline draft retention, conflict recovery and trash passed the dedicated [browser validation](assets/ui-audit-2026-10-20/documents-validation.log).
- Attachment drop, list display and popup text preview worked. Escape returned focus to the attachment opener.
- The Group menu returned focus to its trigger on Escape. WebKit shared selects opened from the keyboard and returned focus to the original select on dismissal.
- Table column actions appear on hover/focus and remain discoverable on touch. Task and column reordering already have reusable keyboard mechanisms outside the Kanban gap.
- The large-board test rendered **64 detailed DOM objects** for **5,000 objects / 2,000 connectors**, opened in **616ms**, and measured **54ms p95 pan samples**. Held-pan preloading, continuous zoom, overview bitmap rendering, two-finger gestures and pressure-sensitive drawing checks passed. These are local test results, not device-independent frame-rate guarantees. [Performance log](assets/ui-audit-2026-10-20/canvas-performance.log)
- No broad light/dark text contrast problem was found in the scanned task fields or settings. The contrast finding is specifically the custom sticky-note fill described in F09.
- No confirmed use of a separate native colour field was found: the legacy-looking colour branch delegates to the shared picker. Keep that implementation.
