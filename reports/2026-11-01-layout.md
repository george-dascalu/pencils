# Layout refinement — 2026-11-01

Released in Pencils 0.20.123 on 2026-11-01. Scope: refine the existing Operate/Read interface; retain compact controls, shared tokens, both themes, saved Home layouts and existing navigation actions.

## Spatial direction

Project navigation and actionable work lead. Project context supports them. Home's Projects panel should contain project links at panel scale, while Overview should show compact metrics followed by deadlines, with background information beside them on wide screens and below them on phones. Related text/actions stay together with 4/8/12/16px spacing; separate sections have more room. DOM and visual order agree.

## Findings and changes

- **Home:** the Projects panel embedded a full organisation page. On desktop its 168px body had 1,158px of scrollable content, with the first project at y1043; on phone the first project appeared at y1172. It now renders compact project links directly, preserving the current organisation, project-open handlers, vault warnings and empty-state Create/Example actions. Saved panel sizes and the rest of Home are unchanged. Cross-project Markdown reference data still loads.
- **Overview:** large metrics and About/status content put the first phone deadline at y730. Metrics now occupy 157px rather than 233px on phone; deadlines come first in DOM and reading order, with a wider column on desktop. Context uses its content height rather than stretching to the deadline list; the empty bordered tail fell from 307/320px to 17px. Dates have a nonshrinking single-line slot beside wrapping titles.
- **Help:** navigation opened above 780px while the page stayed single-column through 800px. At 790/800px the expanded guide list put the article at y895. Its opening breakpoint now matches the 800px layout breakpoint.
- **Capacity:** setup buttons touched, and an unbroken title could become 2064px wide and push the assignee beyond x2080 inside a 378/796px row. Grouped actions now have an 8px gap; titles and metadata shrink/wrap within their row. Short metadata keeps its natural width (79px in the sample), preserving a 44px normal phone row. The existing ID/title space was verified and retained.
