# Clearer recovery and offline drawing — 2026-11-01

Released in Pencils 0.20.124 on 2026-11-01. The pass follows the save warning → Recovery → conflict/backup decision and Board tools → offline drawing → reconnect paths. Audience: the owner using several devices, with future small-team use; losing or overwriting edits is the main concern in these flows.

## Message hierarchy

Lead with where the edits are saved, then the next action and its consequence. Keep browser copies, server records, project backups and full installation backups distinct. Retain the existing compact interface and recovery mechanisms.

| Before | After / purpose |
|---|---|
| “On disk”, “Keep my conflicting values”, “Use disk values for conflicts” | “Server version”, “Use my edits”, “Use server edits”. The explanation makes clear that this choice applies to conflicting fields; other edits are combined. |
| “All queued changes are saved” | “No pending saves in this browser”. Does not imply another device or an editor draft has saved. |
| “Retry”, “Verify”, “Restore vault” | “Retry save”, “Verify backup”, “Restore backup”. Restore confirmation names projects and organisations and the backup created before replacement. |
| “Browser draft storage full” | “Browser draft storage unavailable”. The system cannot always distinguish full storage from unavailable storage; the warning still explains both possibilities and how to export. |
| “Conflict — changes kept in Recovery” | “Edits need review — open Recovery & backups”. Names the next action rather than treating a screen as a storage location. |
| “Pending server sync” in the offline pad | “Saved in this browser · not on server”. The gallery explains that offline edits do not sync automatically and gives the path back to Local checkpoints. |
| “Sync checkpoint” | “Apply to board”, beside “Restore as copy”. The explanation distinguishes merging into the original from creating a separate board. |
| “Local canvases”, “Canvas link copied”, “Link canvas to cards” | “Offline drawing”, “Board link copied”, “Link board to cards”. Uses the resource name shown in navigation. |

The terminology glossary in PRODUCT.md and the README reconnect instructions match the interface. Server merge and backup implementations were inspected to verify the consequences; their data behavior is unchanged.

## Issues found while verifying the flow

- Backup confirmations were mounted on `body`, behind the modal Recovery dialog. They were visible to automation but their buttons were blocked by the dialog. The shared confirmation now mounts inside its opener's dialog when present. It keeps its fixed positioning, Cancel, Escape, outside dismissal and focus behavior. This also repairs draft-discard confirmations in Recovery.
- Long offline board names could push save status outside the viewport. The list now wraps, and names can wrap inside their button and heading. No local control heights were introduced.
- Reopening an offline board previously showed only “Local checkpoint”, hiding whether edits were still pending. Its initial status now reflects the stored pending flag; both states are covered.
